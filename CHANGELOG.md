### Added

- `qmd-mcp` stdio MCP server and `qmd mcp` (P5.2): built on rmcp 3.5.1 behind the default-on `qmd-cli` feature `mcp` (tokio stays out of the `qmd` core crate). Speaks both the 2025 handshake and handshake-less 2026-07-28 (`server/discover`, `resultType`/`ttlMs`/`cacheScope`, `_meta`), with upstream's capabilities and dynamic instructions. Tools `query`/`get`/`multi_get`/`status` and the `qmd://{+path}` resource reproduce upstream's output byte-for-byte (a thin `Service` wrapper returns raw results where rmcp's typed model would drop resource `name`/`title`); argument validation reproduces upstream's zod messages. ### Fixed

- `paths::config_file` resolves `<config-dir>/<name>.yml` (upstream `getConfigFilePath`, collections.ts:131-133); P1.1 mistakenly emitted `index-<name>.yml`, so named indexes looked up the wrong config file.
- Whitespace-only file detection during `update` now uses JS `trim()` semantics: a file containing only U+FEFF is skipped while U+0085 (NEL) is indexed, matching upstream `content.trim()`.
- Model URI resolution treats an empty `models.embed`/`rerank`/`generate` config value as unset and falls through to `QMD_*_MODEL`, matching upstream's `||` chain (previously it skipped the environment variable).
- `Qmd::search`/`vector_query`/`expand_query` resolve backend configuration before locking the connection — resolving a lazy backend on a `DbOnly` config source inside the guard previously deadlocked (config load re-locks `conn`).
- Local config discovery now checks `.qmd/index.yaml` (preferred) and `.qmd/index.yml`, matching upstream — P1.1 mistakenly looked for `qmd.yml`.
- Cached models are no longer deleted when Hugging Face is unreachable. The lazy embed/generate/rerank backends resolved models through `pull_models`, whose etag HEAD ran on every first use; a failed HEAD triggered a refresh that removed the cached GGUF and then could not re-download it (offline `embed`/`query`/`qmd mcp` destroyed working models). Runtime loading now goes through the new `download::resolve_model` — upstream's `resolveModel`/`resolveModelFile`: a cached file is used without any network call, only a missing one is downloaded. `pull` keeps its etag refresh but sweeps the cache only on `--refresh`, a confirmed etag mismatch or an empty cache — upstream's delete-on-failed-HEAD stays unreplicated (parity-matrix §8). Every Hub request now has 30 s DNS/connect/send/response-header timeouts instead of hanging forever on a stalled connection.

### Changed

- `Qmd::search`/`vector_query`/`expand_query`/`search_vector` no longer hold the connection lock during embedding, reranking or query expansion (P5.1, parity-matrix deviation 43): each SQL step locks briefly, so one slow inference no longer blocks other calls on a shared `Qmd`.
- The macOS `GGML_METAL_NO_RESIDENCY` workaround (and its `QMD_METAL_KEEP_RESIDENCY` opt-out) is removed: llama.cpp backends now free their Metal resources on drop (#64), so Metal residency sets stay at llama.cpp's default and the crate no longer mutates the process environment. Drop `Qmd` before process exit on macOS.
- Complete rewrite: this workspace is being rebuilt from scratch as a Rust port of [tobi/qmd](https://github.com/tobi/qmd) v2.8.3. The previous implementation is archived at tag `archive/v0.5.0-abandoned`.
