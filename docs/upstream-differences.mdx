Deliberate deviations from `tobi/qmd` — each is also registered in the
parity matrix in `meme-study`:

- **Single binary, no package dir.** The `skills/` tree is embedded via
  `include_str!` (a byte-verbatim copy of upstream `skills/meme`) and
  materialized under `<cache>/meme/skills/<version>` when `skills path`
  or `skill install` needs a real path. `MEME_SKILLS_DIR` still overrides
  discovery wholesale. Upstream's `skills/release` maintainer skill is
  not ported, so `skills list`/`get --all` show `meme` only.
- **Index naming.** Databases are `~/.cache/meme/<index>.sqlite`
  (global) and `.meme/index.sqlite` (project-local), so a Rust and
  an upstream index can coexist without clobbering each other.
- **Embed locking.** `meme embed` takes an OS `try_lock` on
  `<db>.embed.lock` instead of upstream's directory-level PID file;
  a busy lock prints `Another embed process is already running.
  Skipping.` and exits 0.
- **AST grammars are statically linked.** `meme status` always reports
  `AST Chunking: active` with the full language list — upstream's
  grammar-download failure paths (`Unavailable: <lang>` rows, the
  `unavailable` fallback state) do not exist here.
- **Unnoted crash paths** (e.g. `skill show`/`--skill` with no skill,
  invalid `--chunk-strategy`) print the upstream message plus the doctor
  hint instead of a Bun stack dump.
- **`meme mcp`** serves the upstream tools and resource byte-for-byte
  modulo branding (tool descriptions, `meme://` URIs, server name)
  over stdio and HTTP (`--http`, `--daemon`, `stop`), but
  `meme mcp <anything>` other than `stop` exits 1 instead of silently
  starting a server, and a checked-in `.meme` config's models go through
  the trust gate like every other command.
- The embedded `SKILL.md` is rewritten for this product (`name: meme`,
  `cargo install meme-bin`, `mcp__meme__*` tool names) — it is not a
  verbatim copy of upstream's.
