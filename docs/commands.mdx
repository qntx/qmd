All commands share the search/output options where applicable:
`-c/--collection` (repeatable), `-n`, `--all`, `--min-score`,
`--format cli|json|csv|md|xml|files` (the legacy `--json`/`--csv`/
`--md`/`--xml`/`--files` flags remain aliases), `--filter '<json>'`,
`--full`, `--full-path` and `--explain`.

## Retrieval

| Command | Purpose |
| --- | --- |
| `qmd search <query>` | BM25 keyword search — no LLM involved |
| `qmd query <query>` (alias `deep-search`) | Query expansion + hybrid RRF + reranking — recommended |
| `qmd vsearch <query>` (alias `vector-search`) | Pure vector similarity — no reranking |
| `qmd get <file>[:from[:count]]` | Fetch a document by path or `#docid` |
| `qmd multi-get <pattern>` | Fetch many docs by glob or comma list |
| `qmd ls [collection[/path]]` | List collections or files |

### `qmd query`

`query` accepts either a plain question or a multi-line structured
document of `lex:`/`vec:`/`hyde:`/`intent:`/`expand:` lines — see
[Query syntax](/docs/query-syntax). On top of the shared options:

- `--intent <text>` sharpens ranking (overrides a document `intent:` line)
- `--candidate-limit <n>` caps the per-list candidate pool
- `--no-rerank` skips the LLM reranking step (faster, lower quality)
- `--chunk-strategy auto|regex` selects the tokenizer strategy used for
  hyde/vec text handling (`auto` adds AST breakpoints for code files)

### `qmd vsearch`

Pure vector search — embeds the query, runs sqlite-vec kNN, no
expansion and no reranking. Useful as a quick semantic probe; `query`
is the better default.

## Models

### `qmd embed`

Generates vector embeddings for all documents whose content hash lacks
one — the step that makes `vsearch`/`query` produce vector results.

```bash
qmd embed [options]
  --force                  # clear all vectors and re-embed from scratch
  -c, --collection <name>  # embed only this collection
  --max-docs-per-batch <n> # docs per embedding batch
  --max-batch-mb <n>       # input megabytes per batch
  --chunk-strategy <auto|regex>
  --timeout <minutes>      # 0 = no limit (default 30)
```

`embed` takes an exclusive lock on the index database; a second
concurrent run prints `Another embed process is already running.
Skipping.` and exits 0. With no pending work it exits early —
`✓ All content hashes already have embeddings.` — without touching
the model.

### `qmd pull`

Downloads (or re-validates) the three configured models — embed,
generate and rerank — into the model cache. Never opens the index.

```bash
qmd pull [--refresh] [--progress]
  --refresh   # delete cached files and re-download
  --progress  # byte-progress line on stderr (TTY only)
```

`pull` re-downloads a model only on `--refresh` or when the Hub reports
a newer etag; if the Hub is unreachable, cached models are kept as-is.
Commands that load models (`embed`, `vsearch`, `query`, `qmd mcp`) use
the cached file directly and only download a model that is missing.
Network requests time out after 30 s of no connection or no response.

Model selection order, like upstream: `models:` pinned in `index.yml` >
`QMD_*_MODEL` environment > built-in defaults. Local file paths are
accepted as model URIs (handy for air-gapped setups); anything starting
with `hf:` resolves through the Hugging Face cache layout.

## Diagnostics

### `qmd doctor`

Runs the full health report: SQLite/sqlite-vec versions, `index.yml`
validity and collection count, environment overrides with their
consequences, model defaults vs. configured models, model-cache GGUF
validation, device mode and a native GPU probe (skip with
`QMD_DOCTOR_DEVICE_PROBE=0`, force CPU mode display with
`QMD_FORCE_CPU=1`), embedding freshness/fingerprint groups and a
vector-sample reproduction check. Findings end in a deduplicated
`Recommended next steps` list.

## Skills

`qmd skills` and `qmd skill` expose the bundled QMD skill — agent
instructions for driving the CLI — byte-identical to upstream's copy.
The tree is embedded in the binary; set `QMD_SKILLS_DIR` to point at a
real directory instead.

| Command | Purpose |
| --- | --- |
| `qmd skills list` | List bundled runtime skills (`hidden:` entries are excluded) |
| `qmd skills get <name>` | Print a skill's `SKILL.md` |
| `qmd skills get <name> --full` | Also print `references/`/`templates/`/`scripts/` files |
| `qmd skills get --all` | Print every runtime skill |
| `qmd skills path [name]` | Print the skills search dir, or one skill's dir |
| `qmd skill show` | Print the `qmd` skill (also `qmd --skill`) |
| `qmd skill install [--global] [--yes] [-f]` | Install under `./.agents/skills/qmd` (or `~` with `--global`) |

`skills` accepts `--json` — errors return `{"success":false,"error":...}`
on stdout. `skills path` and `skill install` materialize the embedded
tree under `<cache>/qmd/skills/<version>` (the port has no package
directory; upstream resolves it next to the binary).

`skill install` writes a bootstrap `SKILL.md` that defers to `qmd skill
show`, then offers to create `.claude/skills/qmd` as a relative symlink:
`--yes` accepts immediately, a TTY prompts `[y/N]`, and non-interactive
runs print a `Tip:` line instead. `-f/--force` replaces an existing
install or link path; if `.claude/skills` already resolves to
`.agents/skills`, the link is skipped as already visible.

## MCP server

`qmd mcp` runs a [Model Context Protocol](https://modelcontextprotocol.io)
server over stdio for agents and IDEs. It speaks both the 2025 protocol
(initialize handshake) and 2026-07-28 (no handshake, `server/discover`),
and exposes the same surface as upstream:

| Tool / resource | Purpose |
| --- | --- |
| `query` | Hybrid search — plain `query` (auto expansion) or typed `searches` (`lex`/`vec`/`hyde`), with `intent`, `filter`, `collections`, `limit`, `minScore`, `candidateLimit`, `rerank` |
| `get` | One document by path or `#docid`, optional `:from[:count]` suffix |
| `multi_get` | Many documents by glob, comma list or docids, capped by `maxBytes` |
| `status` | Index and collection summary |
| `qmd://{+path}` | Read a document as a resource |

stdout carries JSON-RPC only; logs go to stderr. When stdin closes the
server prints `Shutting down (stdin closed)...`, waits up to 5 s for
in-flight calls and exits 0. `qmd mcp <anything>` other than `stop` is
rejected with exit 1 (upstream would start a server).

## MCP over HTTP

`qmd mcp --http [--port N] [--host H]` serves the same protocol surface
over HTTP — port defaults to `8181`, the host comes from `--host`, then
`QMD_HOST`, then `localhost`. Endpoints, matching upstream:

| Route | Purpose |
| --- | --- |
| `POST /mcp` | Stateless MCP — SSE responses for the 2025 era, plain JSON for 2026-07-28 (`_meta`/`MCP-Protocol-Version` requests) |
| `GET /health` | `{"status":"ok","uptime":<seconds>}` |
| `POST /query`, `POST /search` | REST structured search — `{"searches":[...]}` → `{"results":[...]}` |

Origin and Host headers are checked before routing
(`QMD_ALLOWED_ORIGINS` / `QMD_ALLOWED_HOSTS` — a wildcard bind without a
host allowlist prints upstream's warning and skips Host validation);
rejections are `403` with a `-32003` body. SIGINT/SIGTERM print
`Shutting down (SIGINT|SIGTERM)...` and exit 0; an occupied port prints
`Port <n> already in use`.

### Daemon mode

`qmd mcp --http --daemon` re-launches the server detached: the launcher
prints `Started on http://<host>:<port>/mcp (PID <n>)` plus `Logs:
<path>` and exits; the child writes its stdout/stderr to
`$XDG_CACHE_HOME/qmd/mcp[-<index>].log` (`~/.cache/qmd` without XDG) and
its PID to the sibling `.pid` file. A live pidfile refuses with
`Already running (PID <n>)`; a stale or recycled one is removed.
`qmd mcp stop` reports `Not running (no PID file).`, cleans a stale
file, or SIGTERMs a verified qmd PID (`Stopped QMD MCP server (PID
<n>).`) — identity is confirmed by the process command line so a
reused PID is never signalled. `qmd status` adds a green `MCP:
running (PID <n>)` line while the daemon is alive.

## CI behavior

`CI=<anything non-empty>` disables real LLM operations — expansion,
reranking and embedding fail fast with
`LLM operations are disabled in CI`. `search` and `lex:`-only `query`
documents keep working (they never touch a model), as do `doctor`'s
SQL-level probes.
